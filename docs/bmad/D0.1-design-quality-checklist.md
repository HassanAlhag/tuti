# D0.1 — Tuti Design Quality Checklist
## Design Audit Standard · Customer Web · v1.0

> This document is the authoritative standard for evaluating every customer-facing
> screen before implementation. All screens must pass before they ship.

---

## 1. What "Premium" Means for Tuti

Tuti is a luxury gifting marketplace. Premium is not decoration — it is restraint
with intent. A screen is premium when:

- **Every element earns its place.** Negative space is a design choice, not
  an oversight.
- **Warmth and elegance coexist.** Forest green, cream, and gold feel curated,
  not corporate.
- **The product is the hero.** Perfume bottles, cakes, and gift boxes deserve
  generous staging, never crowd-clipped cards.
- **Hierarchy is immediate.** A visitor knows within 2 seconds what this screen
  is for and what to do next.
- **Transitions feel considered.** No jarring jumps. Reveal animations are gentle,
  purposeful.
- **Typography carries the brand.** Inter at the right weight and size reads as
  both editorial and trustworthy.

---

## 2. What "Durable UI" Means for Tuti

Durability means the design does not collapse under real-world conditions:

- **Works at every content length.** Long product names, short seller names, missing
  images, empty states, single-item carts, 30-item carts — all handled without breaking.
- **Scales with screen size.** 320px mobile to 1920px desktop with no layout drift.
- **States are explicit.** Every interactive element has default, hover, focus, active,
  disabled, loading, error, and empty states.
- **Spacing is systematic.** Gaps come from the token scale (`--sp-*`), not ad-hoc
  values. Changing the scale should reflow predictably.
- **Radius and shadow are consistent.** Cards all use the same radius tier. Shadows
  have a defined depth story (xs → strong).
- **Color is semantic.** Green = brand/action. Gold = accent/premium. Red = error.
  Amber = warning. Never used decoratively in conflict with their meaning.

---

## 3. Design Direction: The Three Pillars

### Pillar 1 — Glass Depth & Restraint

Surfaces should have soft material feel. Depth is created through:

- Translucent panels with `backdrop-filter: blur(12–24px)` on overlaid surfaces
- Warm white panels (`--panel: #fffdf8`) set against cream paper (`--paper: #fbf7ef`)
- Shadow tiers: `--shadow-xs` for resting, `--shadow-soft` for lifted,
  `--shadow-strong` for modals
- Thin warm borders (`--line: #d9ded7`) that separate without harshness
- **Restraint:** glass effects on 1–2 surfaces per screen maximum (topbar, one panel).
  Not every card.

### Pillar 2 — Infrastructure-Grade Durability

Inspired by AWS-style reliability, scalable layout systems, and durable product UI.
Structure before style. Every section should:

- Be constructed from a repeatable layout primitive (grid, card, section, panel)
- Respond to the same breakpoint logic (520 / 820 / 1180)
- Have a predictable empty state, loading state, and error state
- Use semantic HTML elements (`article`, `section`, `nav`, `main`, `aside`)
- Be identifiable by a CSS class naming convention (`cl-*` for layout, `pc-*` for
  product card, `is-*` for immersive story, `bab-*` for Build a Box)

### Pillar 3 — Elegant Gold Touches

Gold (`--gold: #d7a84a`) should feel like a finishing detail:

- **Correct uses:** star ratings, premium badges, price emphasis on hero cards,
  thin top-border accent on featured sections, selected/active tab indicator
- **Wrong uses:** buttons, backgrounds, large fills, icon-heavy sections
- Frequency: at most 2 visible gold elements per screen at rest
- Gold must never appear on the same surface as the forest green (`--brand`) without
  deliberate separation — they compete

## 4. Design Mistakes to Avoid

| Mistake | Why It's Wrong | Tuti Rule |
|---|---|---|
| Too much gold | Cheapens the premium signal; reads as costume jewellery | Max 2 gold touches per screen |
| Cheap gradients | Gradient backgrounds with high saturation feel dated and low-end | Only warm-neutral gradients (cream → light cream); no rainbow |
| Noisy glass effects | Blur on too many surfaces creates visual noise | Glass on 1–2 surfaces maximum per screen |
| Weak contrast | Muted text on muted backgrounds fails accessibility and trust | Body text ≥ 4.5:1 contrast; headings ≥ 3:1 |
| Crowded cards | Products deserve breathing room | Cards must have ≥ 16px internal padding on all sides |
| Inconsistent radius/shadow | Mismatch destroys visual cohesion | Cards use `--radius-lg` (16px); modals `--radius-xl` (24px); chips `--radius-full` |
| Random section spacing | Each section feeling arbitrarily spaced breaks rhythm | Section vertical gap: 4rem (mobile), 6rem (desktop) minimum |
| Luxury visuals without conversion | Beautiful screen that doesn't drive next action | Every screen must have exactly one primary CTA visible without scrolling |
| Decorative icons without purpose | Icons as noise rather than wayfinding | Every icon must reduce reading effort; never purely decorative |
| Dense typography | Premium reads slow; walls of text are not editorial | Max 65 characters per line of body copy; ample leading |

## 5. Scoring Rubric (1–5)

Each dimension is scored 1–5. A screen needs a **minimum score of 4** on every
dimension to ship. A score of 3+ on all dimensions with no hard fails qualifies
for a CONDITIONAL pass during early audit (see Section 6).
Any dimension scoring 1 is an automatic fail.

| # | Dimension | 1 — Unacceptable | 3 — Acceptable | 5 — Excellent |
|---|---|---|---|---|
| 1 | **Brand fit** | Feels generic or mismatched | On-brand colour usage but weak personality | Immediately identifiable as Tuti; warm, curated, editorial |
| 2 | **Luxury / premium feel** | Feels cheap, busy, or low-effort | Clean but not distinctive | Generous space, restrained decoration, product at centre |
| 3 | **Glass depth & restraint** | Flat, no material sense | Some surface differentiation | Layered surfaces with appropriate blur, shadow, and translucency |
| 4 | **Durable system design** | Breaks at edge cases; no states | Most states handled; layout holds | Every state defined; layout is predictable from any breakpoint |
| 5 | **Visual hierarchy** | Unclear what to look at | Primary action findable after scanning | Eye lands on primary action < 2 seconds; clear F/Z reading path |
| 6 | **Spacing & rhythm** | Ad-hoc gaps; inconsistent | Mostly token-based; minor deviations | All spacing from token scale; section rhythm feels deliberate |
| 7 | **Typography** | Wrong sizes, weights, or mixed styles | Readable; consistent scale | Perfectly weighted; editorial hierarchy; correct line length |
| 8 | **Imagery** | Missing, stretched, or clipped | Present and correctly sized | Product-forward, generous staging, consistent art direction |
| 9 | **Gold accent usage** | Gold used as background or on buttons | Gold used sparingly but in low-value positions | Gold appears only at moments of premium signal; max 2 per screen |
| 10 | **Colour & contrast** | Fails WCAG AA | Passes most contrast checks | Passes WCAG AA fully; colour is semantic and consistent |
| 11 | **Conversion clarity** | No clear next action | Primary CTA present but not prominent | One clear primary CTA, above fold, immediately scannable |
| 12 | **Responsiveness** | Layout broken at mobile or large desktop | Works at 375 and 1440 | Fluid across 320–1920; no overflow; touch targets ≥ 44×44px |
| 13 | **States** | Only happy path designed | Loading and error states exist | All states: default, hover, focus, active, disabled, loading, error, empty |
| 14 | **Accessibility** | No ARIA, poor contrast, keyboard traps | Some ARIA; passable contrast | Full ARIA, keyboard nav, skip links, WCAG AA throughout |

## 6. Pass / Fail Rules

### Hard Fail (any one of these = screen cannot ship)

- Any dimension scores **1**
- Body text contrast below **4.5:1** against its background
- Primary CTA is **not visible without scrolling** on a 375px viewport
- Interactive elements with **no focus indicator**
- Gold used as a **button fill** or **section background**
- More than **3 gold elements** visible simultaneously at rest
- Glass blur applied to **more than 2 surfaces** on the same screen
- A card with **no empty state** defined
- Layout breaks (overflow, truncation, collapse) at **375px or 1440px**
- Modal or drawer with **no keyboard escape** (Escape key closes)

### Soft Fail (must be remediated before final ship; reviewer discretion)

- Dimension score of **2** on any category
- Icon present without a visible or screen-reader label
- Section vertical gap deviates from the 4rem/6rem rhythm without justification
- Radius value that does not match the defined tier (sm/md/lg/xl/full)
- Shadow level that does not match the defined tier (xs/sm/soft/md/strong)
- Font weight used outside the defined scale (400/500/600/700/800)

### Audit Stage Decision Rules

| Stage | Condition | Decision |
|---|---|---|
| **Early audit** | All dimensions ≥ 3 · no hard fails | CONDITIONAL — may proceed to implementation with listed remediations |
| **Early audit** | Any dimension < 3 or any hard fail | FAIL — do not proceed |
| **Final ship** | All dimensions ≥ 4 · no hard fails · all soft fails resolved | PASS |
| **Final ship** | Any dimension < 4 or any unresolved soft fail | FAIL — do not ship |

A CONDITIONAL pass is a time-bounded approval. Remediations must be completed before
the screen is marked PASS. A screen should not remain in CONDITIONAL state for more
than one sprint.

## 7. Human Taste Rule

Automated tools can catch layout issues, contrast failures, accessibility violations,
responsiveness breakpoints, and visual regression. They cannot fully judge luxury,
taste, emotional quality, or brand desire.

**Every major screen must receive one human design review pass before implementation
approval.** This review is not a box-ticking exercise — it is a qualitative judgment
about whether the screen would be at home on a premium gifting platform.

Questions a human reviewer should answer:

- Does this screen make me *want* to buy something?
- Does it feel like it belongs next to a luxury perfume boutique?
- Would I be proud to show this to a high-value customer?
- Is there anything that feels cheap, rushed, or generic?
- If I removed all the brand colours, would the layout still feel considered?

If the answer to any of the last four questions is "no" or "maybe," the screen is not
ready regardless of its automated scores.

Human reviewers should document their qualitative judgment in the audit record under
a "Taste notes" section alongside the scoring table.

## 8. Screen-by-Screen Audit Workflow

For every screen, follow this sequence:

### Step 1 — Orientation (before opening code)

- State the screen's single job in one sentence
- Identify the one primary conversion action
- Identify the three things a user needs to see first

### Step 2 — Mobile-first visual pass (375px)

- Does the above-fold area contain: heading + subtext + primary CTA?
- Is there any horizontal overflow?
- Are all touch targets ≥ 44×44px?
- Does the layout collapse gracefully or feel broken?

### Step 3 — Desktop visual pass (1280px)

- Does the layout make good use of horizontal space without stretching?
- Is the max content width respected (`--max-width: 90rem`)?
- Do sections breathe (≥ 6rem vertical gap)?

### Step 4 — Score all 14 dimensions

- Fill the scoring table (template in Section 9)
- Flag any hard fail immediately
- Note soft fails for remediation

### Step 5 — State audit

Walk through each interactive element and confirm:

- [ ] Default
- [ ] Hover (cursor pointer; subtle visual change)
- [ ] Focus (visible outline; not just browser default)
- [ ] Active / selected (clear visual differentiation)
- [ ] Disabled (reduced opacity; no pointer events)
- [ ] Loading (spinner or skeleton; button disabled during request)
- [ ] Error (red tint; message; not silent)
- [ ] Empty (meaningful message; entry point offered)

### Step 6 — Accessibility spot-check

- [ ] All images have meaningful `alt` text (or `alt=""` if decorative)
- [ ] All interactive elements reachable by Tab
- [ ] All modals/drawers: focus trapped inside, Escape closes, focus returns on close
- [ ] Colour is never the only differentiator (e.g., error also has an icon/text)
- [ ] Form fields have visible labels (not placeholder-only)
- [ ] Dynamic regions use `aria-live` where needed

### Step 7 — Human taste review

- Answer the five qualitative questions from Section 7
- Record taste notes alongside the scoring table
- This step cannot be skipped for screens in Priority 1–10

### Step 8 — Decision

- **Pass:** all 14 dimensions ≥ 4, no hard fails, taste review complete
- **Conditional pass (early audit only):** all dimensions ≥ 3, no hard fails,
  remediations listed
- **Fail:** any hard fail, or any dimension ≤ 2, or taste review fails

## 11. Current Design Baseline (Observed, June 2026)

The following is a factual summary of the current implementation state.
It is a starting point, not a pass/fail judgment.

**What exists and is consistent:**

- Token system with forest green brand, cream paper, warm shadows — correct direction
- Topbar glass blur (`backdrop-filter: blur(18px)`) — on-brand, glass-direction
- Warm shadow system with green-tinted dark (`rgba(23,23,23,*)`) — appropriate
- Semantic font scale in Inter — correct
- Radius token system — exists but usage consistency across components unknown
- Gold token exists (`--gold: #d7a84a`) — usage rules now formally defined in this document
- ProductCard: dense information but well-structured (seller name, chip, title, summary,
  meta, rating, price, actions)
- ImmersiveStory: full-viewport scroll narrative — editorial and brand-appropriate
- BottleArt: SVG fallback for missing product images — avoids broken image states

**What requires attention before design audit:**

- Glass effects currently limited to topbar; no defined glass panel component
- Gold usage has been ad-hoc — this document establishes the formal rules
- Section spacing rhythm needs measuring against the 4rem/6rem standard
- Card radius consistency across ProductCard, GiftBoxCard, CakeCard not yet audited
- AuthModal has no observed blur/glass treatment
- Checkout form is functional but spacing density not yet audited
- Empty states, loading skeletons, and error states exist in some screens but not
  formally audited against this checklist
- Colour contrast has not been formally checked against WCAG AA across all screens
